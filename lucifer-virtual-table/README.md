# Lucifer Virtual Table

Самостоятельный виртуальный стол на Next.js / React, Node.js и PostgreSQL. Интерфейс на русском. Основные записи, аккаунты, сессии, кампании и загруженные карты хранятся в PostgreSQL. Облачная база и аккаунт ChatGPT не нужны.

## Локальный запуск

Нужен Node.js 24. Из этой папки:

```powershell
npm ci
npm run local
```

Открыть http://127.0.0.1:5173. Скрипт запускает отдельную PostgreSQL на 127.0.0.1:55432, применяет миграции и поднимает приложение. Существующий сервер PostgreSQL компьютера не меняется.

Из родительской папки можно выполнить `powershell -File D:\VTT\Start-Lucifer.ps1`.

Для запуска собранного приложения:

```powershell
npm run build
npm run local:production
```

При раздельном запуске: `npm run db:local` → в другом терминале `npm run db:migrate` → `npm run dev`.
Локальный кластер использует настоящие нативные PostgreSQL-бинарники через embedded-postgres. Это не SQLite и не браузерная эмуляция. Данные находятся в `var/postgres`, журнал — `var/postgres.log`. Пароли генерируются случайно, записываются только в игнорируемые `var/postgres-credentials.json` и `.env.local`. Роль приложения `lvt_app` не имеет прав суперпользователя.

Создайте свой аккаунт на /login. Демонстрационный стол до сохранения существует только в памяти страницы. В личном кабинете можно создавать миры, продолжать свои кампании, менять профиль, цвет костей и пароль. При смене пароля сессии на других устройствах завершаются.

## Возможности

- Сцены: квадратная / гексагональная сетка, произвольный масштаб, свои PNG/JPEG/WebP-карты до 10 МБ, панорамирование, зум, полный экран сцены.
- Токены: перемещение с привязкой к клетке, лист персонажа, произвольные характеристики, здоровье, защита, инициатива, состояния, владелец, скрытие.
- Редактор карт: комнаты, коридоры, многоугольники, 9 материалов, 18 объектов, стены, двери/окна, подписи, слои с блокировкой, выделение/перемещение/размер/поворот, копирование, отмена/повтор, локальный черновик, импорт/экспорт JSON и изображения SVG/PNG ×2. Сохранение геометрии в PostgreSQL вместе с кампанией.
- Туман войны автоматически открывается от токенов отряда или только собственных токенов; стены блокируют обзор. Двери открывают проход и видимость, окна пропускают взгляд. Ручные области тоже доступны.
- Режимы 2D / Изометрия / 3D: общий стол и координаты, объёмные стены/объекты, текстуры материалов, камера, модели героев и монстров. 22 локально включённые модели с CC0; несколько классов используют общую визуальную основу. Для записи бестиария без точной фигуры используется базовая модель, которую может изменить ГМ.
- Бой: инициатива, ходы, раунды, суммарный бюджет движения, действие/бонус/реакция, рывок/уклонение, атаки против AC, критические попадания, спасброски, урон/лечение, ячейки, базовая концентрация и состояния, области и визуальные эффекты. Игрок ограничен скоростью только в бою и в свой ход. ГМ перемещает любую фишку свободно, без расхода бюджета игрока.
- Общие сохранённые комнаты передают перемещения во время перетаскивания через SSE и PostgreSQL LISTEN/NOTIFY. При одновременном управлении ГМ отменяет жест игрока; поздние пакеты игрока отклоняются сервером.
- Журнал с общими и секретными заметками, макросы, поиск.
- Общий чат, публичные и секретные броски, серверная генерация результата через криптографический генератор без смещения по модулю.
- Трёхмерные кости на Three.js и cannon-es: вращение, отскоки, столкновения, освещение, тени, отключаемые звуки. D100 показан парой d10. Настраиваемый цвет и сокращённая анимация.
- Приглашения на 24 часа для 8 игроков, проверка членства и прав на каждом запросе. Игрок не может выдать себе права ведущего или изменить чужого героя.
- JSON-экспорт/импорт содержимого кампании. Загруженные бинарные карты и история чата не включены в JSON; полная резервная копия базы включает их.

## Универсальные кости

| Механика | Пример |
| --- | --- |
| Любой целый dN (2…1 000 000 000) | `3d24+2` |
| Процентные | `1d100`, `d%` |
| Преимущество / помеха | `2d20kh1`, `2d20kl1` |
| Отбросить низшую | `4d6dl1` |
| Взрывы / заданный порог | `4d6!`, `2d10!>=9` |
| Переброс / однократный | `4d6r=1`, `4d6ro<3` |
| Пул успехов / штрафы за провалы | `8d6>=5`, `8d10cs>=8cf=1` |
| Fate / Fudge | `4dF+2` |
| Символьные / свои грани | `3d[oracle]` |
| Скобки и арифметика | `(2d8+4)*2` |

Редактор системы позволяет задавать свои характеристики и кости: ID, название и массив граней `{label,value,symbols?}`. Пары противоположных символов могут погашаться. Пример загружается кнопкой в редакторе. Поддерживается до 200 костей в группе и до 1000 результатов с учётом взрывов/перебросов; бесконечные формулы отклоняются. Формулы не выполняют JavaScript.

Это универсальное ядро, а не заявление о полной автоматизации всех изданных ролевых систем. Профили d20, d100, пулов d6 и Fate служат отправными точками. Встроенный каталог открытого SRD 5.1 (2014) содержит 334 монстра, 319 заклинаний, 9 рас, 4 подрасы, 12 классов/подклассов, черты, способности, состояния и снаряжение. Создание персонажей и добавление монстров используют эти данные. Названия частично переведены, оригинальные описания преимущественно на английском. Полные платные книги D&D не входят. [Источники SRD](public/licenses/SRD-ATTRIBUTION.txt), [модели](public/licenses/MODELS.txt).

Каталог не означает полную автоматизацию D&D. Особые условия, сложные классовые способности, зарядки/перезарядки, распределение нескольких лучей по разным целям, предметы и многие длительные/утилитарные заклинания пока разрешает ведущий. Это явно отмечено у действий. Расы/классы рассчитаны по SRD 2014; редакцию 2024/5.2 нельзя смешивать с ними автоматически.

## Развёртывание и пределы

Сборка создаёт Next.js standalone. Готовы Dockerfile, локальный compose.yaml и серверный compose.production.yaml с Caddy HTTPS, отдельной PostgreSQL и секретами из файлов. Пошаговые команды запуска, обновления, резервного копирования и переноса локальной БД находятся в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Комплект Docker не запускался в этой среде, на VPS приложение не разворачивалось.

Основная синхронизация работает через SSE; резервный опрос — 15 секунд при исправном потоке и 1,8 секунды при отключении. Произвольная загруженная 2D-картинка остаётся плоской основой в 3D: объём создают стены/объекты из редактора, а не автоматическая реконструкция изображения. Демонстрационные карты дополнены подготовленным объёмным окружением.

Участник с доступом к карте может скачать её целиком: туман скрывает отображение и сервером отфильтрованные фишки, а не части исходного файла. Открытые области не сохраняются как исследованная карта: обзор следует за фишками; постоянное открытие делает ГМ ручным инструментом. Большие и нестандартные dN используют условную 3D-форму; расчёт вероятностей не зависит от формы. В сцене показываются первые 24 кости, полный результат — в журнале.

Результат броска определяется на сервере. Траектория физического броска предварительно рассчитывается с реальными столкновениями; обозначения граней согласуются с результатом сервера до первого кадра. После приземления кость не доворачивается принудительно. Нагрузочные испытания, WAN-сессия с реальными игроками, SMTP-подтверждение почты, восстановление забытого пароля и аудит безопасности перед публичным запуском ещё не выполнены.

Файлы старого Sites/Cloudflare-стартера и миграции в drizzle/ сохранены как исходный scaffold, но не участвуют в текущем запуске. Рабочая схема — db/migrations/. Созданная ранее приватная Sites-заготовка не опубликована; выбранный режим — локальное приложение с PostgreSQL.
